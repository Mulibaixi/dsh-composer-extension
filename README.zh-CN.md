# dsh-composer-extension

[English](README.md) | [简体中文](README.zh-CN.md)

为 DeepSeek Harness（DSH）的主聊天输入框提供材料联动与任务协调能力，让主模型与翻译插件在同一次任务中协作。

用户可以在翻译工作区准备原稿，在主聊天中说明要求，一次发送完成材料与指令的交接。翻译过程中需要补充背景或处理关键问题时，扩展帮助将请求交回对应的主聊天，减少手工复制材料和反复传话。

## 解决什么问题

- **原稿与要求容易分散**：将翻译工作区的待译材料随主聊天消息一起提交。
- **翻译时可能缺少背景**：在支持的任务中，让翻译模型向主模型请求补充信息。
- **后台任务与主聊天脱节**：在接入的任务阶段提醒所属主模型继续处理，减少用户手动查看进度和传递结果的操作。

这是配套扩展，不是独立翻译工具。翻译执行、会话历史、译文版本和记忆资产由翻译插件管理；本扩展不提供另一套翻译工作区。

## 目前能做什么

| 能力 | 当前作用 |
| --- | --- |
| 联动发送 | 连接主聊天输入框与翻译工作区，一次提交要求和已准备的材料。 |
| 补充信息 | 在翻译插件和所选模型支持时，将翻译中的疑问交给所属主模型处理。 |
| 关键阶段通知 | 为已接入的分析或文档任务传递需要主模型处理的阶段消息。 |
| 停止与失效处理 | 用户停止主模型后，不因迟到的求助重新唤醒；失效通知不会继续作为有效任务处理。 |

实际可用能力由 DSH 构建、翻译插件和所选模型共同决定。安装扩展不意味着所有后台任务都通过它调度，也不保证翻译耗时或结果质量。

项目仍处于开发阶段。完整桌面流程和不同模型组合需要在实际环境中确认。

## 环境与依赖

- 支持本扩展的 DSH 构建，当前配套环境以 `0.2.0-rc.2` 为基础。
- 与本扩展配套构建的 `dsh-translation-plugin`，提供翻译工作区和实际任务。当前配套使用内容协议 3 和任务阶段协议 2。
- 在 DSH 中配置可用模型；翻译模型主动请求补充信息还需要该模型支持工具调用。
- 从源码构建需要 Node.js 22 或更高版本及 pnpm。

**官方原版 DSH `0.2.0-rc.2` 不提供所需的联动发送能力。只安装本扩展不能补齐这一能力，还需要配套 DSH 构建。** 宿主构建所需资料见 [配套补丁](patches/rc2-composer-submissions-v1.patch) 和 [版本信息](patches/source-manifest.json)。本扩展不是 DSH 桌面安装包，也不会自动修改或升级桌面客户端。

## 安装与更新

### 安装

1. 准备配套 DSH 环境及扩展源码，在本项目目录执行：

   ```powershell
   pnpm install --frozen-lockfile
   pnpm build
   ```

2. 在 DSH 插件管理器中，将本目录作为 `dsh-composer-extension` 本地插件安装并启用。
3. 安装并启用匹配的翻译插件，然后重启 DSH。
4. 打开翻译工作区，确认普通模式未提示材料提交能力缺失。

### 更新

1. 在翻译插件中保存需要保留的内容，并备份重要资料。
2. 同时更新两个源码目录，重新安装依赖并构建；先构建 Composer 扩展，再构建翻译插件。
3. 在插件管理器中刷新或重新加载扩展，再重启 DSH；没有刷新入口时可卸载后重新安装同一目录。

更新时核对扩展、翻译插件与 DSH 构建是否匹配。不要在运行中任务尚未结束或结果不明时，将重启视为自动恢复手段。扩展本身不保存可跨重启恢复的任务，重新加载也不会自动重发模型请求。

版本变化见 [CHANGELOG](CHANGELOG.md)。

## 使用说明

### 1. 将材料和要求一起发送

在翻译插件中选择普通模式，填写待译文本或选择受支持的原稿文件，再在主聊天输入框写明本次要求并发送。

同一翻译会话和已保存资料可从不同主聊天继续使用；本次材料交给发送消息的主模型处理。

材料与这次消息一起提交，主模型根据你的意图安排处理。翻译输入框用于原稿，主聊天用于要求、讨论和修改意见。若本次只想聊天，可在翻译插件提供的入口选择**本次不附带**。

材料提交后会保留当次原稿；之后修改草稿不会改写已发送内容。查看结果、纠错或重译，请使用翻译插件的对应操作。

### 2. 处理翻译中的疑问

在支持补充信息的任务中，翻译模型可以提出需要背景或上下文的问题。主模型可提供补充、转为等待用户，或中止对应操作。

这种交互有次数限制，不会无限自动讨论。无法继续时，在主聊天中补充必要说明，并以翻译插件显示的任务状态为准。不是所有文件任务或模型组合都支持主动求助。

### 3. 后台任务完成或需要处理时

已接入的任务会在关键问题、资料变化或结果需要审阅时通知所属主模型；不是每个分块完成都发送提醒。主模型根据实际任务继续处理，你不必为每一步重复发送指令。

切换主聊天后，已有任务的补充请求和通知仍发送到发起任务的主聊天。

用户停止主模型后，迟到的通知不会代替新的用户指令。如果结果未知，应先查询原任务，避免重复启动。后台结果及历史仍在翻译插件中查看。

### 4. 不可用时如何判断

- **联动发送不可用**：先检查是否使用配套 DSH 构建，并确认本扩展与翻译插件均已启用且已重启。
- **没有主动求助**：可能是当前模型或任务未支持该功能，不代表翻译一定失败。
- **没有阶段通知**：并非所有后台流程都使用本扩展；检查翻译插件中的实际进度与错误，不要仅凭主聊天静默重复提交。
- **重启后任务没有继续**：扩展不自动恢复临时交互；回到翻译插件核对原任务，再明确选择下一步。
