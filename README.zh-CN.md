# dsh-composer-extension

[English](README.md) | [简体中文](README.zh-CN.md)

[![许可证：MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

为 DeepSeek Harness（DSH）的主聊天输入框提供材料联动与任务协调能力，目标是逐步支持主会话与不同插件之间的协作交互。

本扩展当前与 `dsh-translation-plugin` 的翻译工作区配合使用。用户可以在工作区准备原稿，在主聊天中说明要求，一次发送完成材料与指令的交接。翻译、润色和审阅过程中需要补充背景或处理关键问题时，扩展帮助将请求交回对应的主聊天，减少手工复制材料和反复传话。

[解决什么问题](#解决什么问题) · [安装](#安装与更新) · [使用说明](#使用说明) · [发展方向](#发展方向) · [项目与文档](#项目与文档)

## 解决什么问题

- **材料与要求容易分散**：将工作区准备的待译材料随主聊天消息一起提交。
- **任务中可能缺少背景**：在支持的任务中，让翻译模型向主模型请求补充信息。
- **后台任务与主聊天脱节**：在接入的任务阶段提醒所属主模型继续处理，减少手动查看进度和传递结果的操作。

翻译执行、会话历史、译文版本和记忆资产由翻译插件管理；Composer 扩展负责材料交接与任务协调。

## 目前能做什么

| 能力 | 当前作用 |
| --- | --- |
| 联动发送 | 连接主聊天输入框与翻译工作区，一次提交要求和已准备的材料。 |
| 补充信息 | 在翻译插件和所选模型支持时，将翻译中的疑问交给所属主模型处理。 |
| 关键阶段通知 | 为已接入的分析或文档任务传递需要主模型处理的阶段消息。 |
| 停止与失效处理 | 用户停止主模型后，不因迟到的求助重新唤醒；失效通知不会继续作为有效任务处理。 |

当前任务协调覆盖已接入的分析与文档阶段，补充交流需要翻译模型支持工具调用。各平台和 DSH 版本的联动补丁要求见下文。

## 发展方向

后续希望将材料联动、主会话与插件任务之间的交流、阶段通知逐步整理为可供不同插件接入的协作能力。

近期以现有翻译、润色和审阅功能稳定可用为前提，逐步减少本扩展与翻译插件的耦合，明确协作交接与业务处理的边界，降低业务变化对扩展的影响。

通用协作是未来目标。当前接口仍围绕翻译场景实现，尚未提供经过验证的多插件通用接入能力。

## 环境与依赖

- 支持本扩展的配套 DSH `0.2.0-rc.2`、`0.2.1-rc.2` 或 `0.2.1-rc.3` 构建。
- 当前翻译工作流需要与本扩展配套构建的 `dsh-translation-plugin`，提供翻译工作区和实际任务。当前配套使用内容协议 3 和任务阶段协议 2。
- 在 DSH 中配置可用模型；翻译模型主动请求补充信息还需要该模型支持工具调用。
- 从源码构建需要 Node.js 22 或更高版本及 pnpm。

受支持版本的官方原版 DSH 需要匹配的宿主补丁才能联动发送。**包含补丁产物的扩展构建可在 Windows 桌面版 DSH `0.2.1-rc.3` 中自动检测和准备补丁，正常完全退出后自动安装，重新打开生效。** 已安装相同补丁时跳过，用户无需另装 Node 或运行独立脚本。

其他环境和旧版仍使用 [0.2.0-rc.2 补丁](patches/rc2-composer-submissions-v1.patch)及其[源码清单](patches/source-manifest.json)，或 [0.2.1-rc.2 补丁](patches/dsh-0.2.1-rc.2-composer-submissions-v1.patch)及其[源码清单](patches/source-manifest-0.2.1-rc.2.json)。rc.3 的[源码补丁](patches/dsh-0.2.1-rc.3-composer-submissions-v1.patch)及[清单](patches/source-manifest-0.2.1-rc.3.json)保留用于构建。新 DSH 版本仍需先更新至已适配的扩展。

## 安装与更新

### 安装

1. 取得包含宿主补丁产物的 `dsh-composer-extension-<版本>.tgz` 分发包，在 DSH 插件管理器的安装输入框中填写安装包的完整路径或下载链接，安装并启用。分发包包含构建产物，使用者无需本地构建。
2. 安装并启用匹配的翻译插件，按插件管理器提示完整重启以载入插件。打开“Composer：联动组件维护”；若提示联动组件已准备、等待安装，再正常完全退出 DSH 并重新打开。
3. 打开翻译工作区，确认普通模式未提示材料提交能力缺失。

### 从源码构建

准备配套 DSH 环境及扩展源码，在本项目目录执行：

   ```powershell
   pnpm install --frozen-lockfile
   pnpm build
   ```

构建完成后，可在 DSH 插件管理器中安装本目录。普通构建不生成宿主补丁模块；自动准备联动组件及生成完整分发包还需完成下文的[补丁产物构建](#构建补丁产物)。

### 更新

1. 在翻译插件中保存需要保留的内容，并备份重要资料。
2. 在插件管理器中依次安装新版 Composer 扩展和翻译插件分发包。源码安装则先更新两个源码目录、重新安装依赖，依次构建 Composer 扩展和翻译插件。
3. 按插件管理器提示完成更新并重启 DSH；源码目录安装可刷新或重新加载扩展，没有刷新入口时可重新安装同一目录。

更新时核对扩展、翻译插件与 DSH 构建是否匹配。不要在运行中任务尚未结束或结果不明时，将重启视为自动恢复手段。扩展本身不保存可跨重启恢复的任务，重新加载也不会自动重发模型请求。

版本变化见 [CHANGELOG](CHANGELOG.md)。

### 联动组件维护

从命令列表选择 **Composer：联动组件维护**，或输入 `/composer-maintenance`，查看状态、重新检测或安排恢复补丁前版本。关闭窗口但仍在托盘运行时，安装助手会继续等待。停用、卸载或重载会撤销本次待安装任务；崩溃或强杀不会授予安装许可。官方更新改变原包时取消旧任务，下次加载重新检测。

备份位于当前用户本地应用数据目录的 `dsh-composer-extension/host-patches/` 下。DSH 无法打开时，完全退出后可运行对应任务目录中的 `apply-host-patch.ps1 -JobPath <job.json> -Recover`。恢复会核验版本与哈希，拒绝覆盖后来升级的安装包。恢复后须主动“重新检测”才重新安排安装。完整桌面退出和重开流程仍需实际环境验收。

### 构建补丁产物

一般构建生成 Host、Client 和退出安装助手。补丁模块由维护者生成后随扩展分发，用户机器不临时编译。准备固定 DSH 源码及其构建依赖、匹配的官方原版 `app.asar` 后执行：

```powershell
node scripts/build-host-patches.mjs --source <DSH源码目录> --archive <原版app.asar>
pnpm build
pnpm pack
```

工具核验固定源码补丁，在提供的源码目录应用补丁并构建，输出到 `dist/host-patches/<版本>/`；包括两个联动客户端模块及修正重启提示的插件管理模块。需要 Node.js 22.19 或更高版本。`--from-build` 可复用已校验源码的现有产物。打包会检查 rc.3 产物和助手完整性，生成文件不提交源码仓库。

## 使用说明

### 1. 将材料和要求一起发送

在翻译插件中选择普通模式，填写待译文本或选择受支持的原稿文件，再在主聊天输入框写明本次要求并发送。

同一翻译会话和已保存资料可从不同主聊天继续使用；本次材料交给发送消息的主模型处理。

材料与这次消息一起提交，主模型根据你的意图安排处理。翻译输入框用于原稿，主聊天用于要求、讨论和修改意见。若本次只想聊天，可在翻译插件提供的入口选择**本次不附带**。

材料提交后会保留当次原稿；之后修改草稿不会改写已发送内容。查看结果、纠错或重译，请使用翻译插件的对应操作。

### 2. 处理翻译中的疑问

在支持补充信息的任务中，翻译模型可以提出需要背景或上下文的问题。主模型可提供补充、转为等待用户，或中止对应操作。

这种交互有次数限制，不会无限自动讨论。无法继续时，在主聊天中补充必要说明，并以翻译插件显示的任务状态为准。不是所有文件任务或模型组合都支持主动求助。

### 3. 后台任务完成或需要处理时

已接入的任务会在关键问题、资料变化或结果需要审阅时通知所属主模型；不是每个分块完成都发送提醒。主模型根据实际任务继续处理，你不必为每一步重复发送指令。

切换主聊天后，已有任务的补充请求和通知仍发送到发起任务的主聊天。

用户停止主模型后，迟到的通知不会代替新的用户指令。如果结果未知，应先查询原任务，避免重复启动。后台结果及历史仍在翻译插件中查看。

### 4. 不可用时如何判断

- **联动发送不可用**：先检查是否使用配套 DSH 构建，并确认本扩展与翻译插件均已启用且已重启。
- **没有主动求助**：可能是当前模型或任务未支持该功能，不代表翻译一定失败。
- **没有阶段通知**：并非所有后台流程都使用本扩展；检查翻译插件中的实际进度与错误，不要仅凭主聊天静默重复提交。
- **重启后任务没有继续**：扩展不自动恢复临时交互；回到翻译插件核对原任务，再明确选择下一步。
